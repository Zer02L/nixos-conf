# Памятка по работе с Git и GitHub (GitHub Flow)

Краткое руководство по созданию веток, отправке изменений, работе с Pull Request (PR) и поддержанию чистоты в репозитории.

---

## 1. Завершение работы после принятия PR (Что делать прямо сейчас)

Когда вы приняли PR на GitHub и нажали кнопку **Delete branch**, изменения смерджены на сервере. Чтобы синхронизировать локальный репозиторий на компьютере:

```bash
# 1. Переключаемся на основную ветку
git checkout main

# 2. Скачиваем влитые изменения из GitHub
git pull origin main

# 3. Безопасно удаляем старую локальную ветку (она уже смерджена)
git branch -d <имя-ветки>

# 4. (Опционально) Очищаем кеш ссылок на удалённые ветки
git fetch --prune
```

## 2. Полный цикл работы над новой задачей (GitHub Flow)

### Шаг 1. Актуализация `main`
Всегда начинайте новую работу со свежей версии проекта:
```bash
git checkout main
git pull origin main
```

### Шаг 2. Создание ветки под задачу
Никогда не коммитьте напрямую в `main`. Создайте ветку с говорящим префиксом:
- `feat/...` — новая функциональность (например, `feat/t3code-dev-tools`)
- `fix/...` — исправление ошибки (например, `fix/sops-decrypt`)
- `chore/...` — рутина, обновление зависимостей, конфигов

```bash
git checkout -b feat/my-feature-name
```

### Шаг 3. Работа над кодом и коммиты
Вносите изменения, проверяйте статус и фиксируйте:
```bash
# Посмотреть изменённые файлы
git status

# Добавить файлы в индекс
git add .

# Зафиксировать изменения с понятным описанием
git commit -m "feat: добавил инструменты разработки T3 Code"
```

### Шаг 4. Публикация ветки на GitHub
При первой отправке ветки передайте флаг `-u` (`--set-upstream`), чтобы связать локальную ветку с сервером:
```bash
git push -u origin feat/my-feature-name
```
*(При последующих коммитах в эту же ветку достаточно просто делать `git push`).*

### Шаг 5. Создание и слияние PR на GitHub
1. Перейдите в репозиторий на GitHub — появится кнопка **Compare & pull request**.
2. Проверьте diff (разницу кода), напишите краткое описание и нажмите **Create pull request**.
3. После проверки нажмите **Merge pull request** -> **Confirm merge**.
4. Нажмите кнопку **Delete branch** на странице PR, чтобы не захламлять репозиторий.

### Шаг 6. Возврат в `main` на компьютере
Повторите действия из раздела 1:
```bash
git checkout main
git pull origin main
git branch -d feat/my-feature-name
```

## 3. Полезные команды и шпаргалка

| Задача | Команда |
| :--- | :--- |
| Посмотреть статус и текущую ветку | `git status` |
| Список всех локальных веток | `git branch` |
| Список всех веток (локальные + удалённые) | `git branch -a` |
| Переключиться на ветку | `git checkout <ветка>` (или `git switch <ветка>`) |
| Создать и сразу перейти в новую ветку | `git checkout -b <новая-ветка>` |
| Отменить незакоммиченные изменения в файле | `git restore <файл>` |
| Принудительно удалить ветку (если не влита) | `git branch -D <ветка>` |
| Посмотреть историю коммитов компактно | `git log --oneline --graph -n 10` |
| Очистить список удалённых веток | `git fetch --prune` |
